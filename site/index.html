awards Put the website in the wind tunnel before anyone sees it.

A plugin for Claude Code and Codex. It designs and builds a site from a written contract, then tests it the way a design-award jury would: %%rules%% audit rules, captures from a real browser, and a juror in a fresh context who scores what it sees.

Nine stations, one file that remembers them

Every build runs the same course. Each station leaves a file on disk; the next station reads that file, not a summary of it. AWARDS.md carries every decision from one session to the next.

  1. Brief

    Seven facts: what only this subject can prove, who reads it and where, the stakes, the assets, the constraints, the routes, the sound.

    AWARDS.md brief

  2. Concept

    Seven candidate worlds; a seeded roll deals three; one question locks the direction.

    direction contract

  3. System

    Two to four colour tokens, one type contract, self-hosted fonts, every browser surface themed.

    DESIGN.md, tokens.css

  4. Structure

    Chapters with beats, one interruption, a designed close and a 404, written as semantic HTML first.

    page map, skeleton

  5. Stack

    Vite by default. Lenis and GSAP on one ticker, and a hook that lets captures drive the page.

    window.__awards

  6. Motion

    One authored moment per chapter, each with a reduced-motion tier. Never a global animation kill.

    motion score

  7. WebGL

    Taken only when a beat needs depth, in its own lazy chunk, with a DOM mirror and a fallback without it.

    GL chunk, or a written decline

  8. Jury

    A juror in a fresh context reads the captures before the contract and ends on one word.

    .awards/jury/

  9. Ship

    The fixes in one batch, the audit clean or every exception explained, the numbers measured.

    .awards/ship/

%%rules%% rules, run after every edit

The audit is deterministic: no model in the loop. In Claude Code it runs after every edit in a project that has an AWARDS.md, and stays silent everywhere else.

Taste you can cite

  • %%sites%% site cards

    Sites read closely, from Site of the Day winners to honourable mentions: palette, type, motion parameters, stack and weaknesses. Every fact is tagged verified, recalled, inferred or unknown.

  • %%patterns%% pattern files

    Narrative models, hero archetypes, motion vocabulary, WebGL dosage and the accessibility paths the winners skipped, each citing the cards it came from.

  • %%recipes%% recipes

    %%recipes-focused%% focused components and one complete page. Each is built with Vite and checked in headless Chromium by its own verifier. See the list.

Two commands

Claude Code

  1. /plugin marketplace add burgisimon/awards
  2. /plugin install awards@awards

Codex

  1. codex plugin marketplace add burgisimon/awards
  2. codex plugin add awards@awards

Then ask for a site with /awards:craft in Claude Code or $awards:craft in Codex. Captures need Node 20.19 or later and Playwright with Chromium; the full requirements are one page away.
