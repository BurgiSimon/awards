# chapter-jump-rail

A chaptered long read with one fixed `<nav>` of real chapter links that is both a jump rail and a scrollspy. The current link follows the chapter whose midpoint is nearest the viewport centre, a rule under each name fills with the reading position, and a jump glides with Lenis, marks its destination at once, then lands with focus on the chapter heading; a key or a drag during the glide stops it where it is. Below 900 px the same list sits behind a sticky ticket that names the current chapter and opens as a disclosure, so the navigation model is the same on every device.

## Why
- **The rail must be links, and it must say where you are.** The jump rail that works is a real `<nav>` of anchors, one per chapter, with a progress bar scrubbed by the scroll `[site:mont-fort]` [verified]; the same card loses points for labels revealed on `mouseenter` only and a rail that is `pointer-events: none` outside the chapters, so here every name is always visible and every link always works. A four-anchor nav whose underline tracks the chapter, plus a fixed pill naming it, shows how little the wayfinding needs to cost `[site:oryzo]` [verified].
- **Answer at the start of the jump.** The page that announces its chapters also moves its nav highlight when a chapter change begins, not when it ends `[site:christoph-nagel]` [verified, `script.js`]. Here the destination is marked the moment the glide starts and held until it lands, so the rail never flickers through the chapters the glide passes over; the fills keep following the real position, which is what makes the trip read as travel.
- **Move focus, and let that be the announcement.** Numbered kickers, chapter buttons, a progress bar and a polite live region naming each chapter come from the same card `[site:christoph-nagel]` [verified]. Without the focus move a keyboard reader who jumps is still in the rail. The focus move is also what a screen reader speaks ("Stage 5, Along the weirs to Callow Bridge, heading level 2"), so this recipe keeps no live region: a status repeating the heading would read every landing twice, and one that talks on every scroll is noise. That is the plugin's choice, not the card's.
- **A jump is a request, not a lock.** Any scrolling input during the glide hands the page back: the glide stops where it is, with no focus move and no hash, and the rail follows the reader from there. Lenis ignores native scrolls while its own glide runs, so stopping the glide itself, not just the landing, is what keeps a key press from being overwritten frame by frame. A plain tap is not a scroll, and the jump still lands. Both are the plugin's own rules.
- **One nav model per device.** The scrollspy pattern hides its index below about 900 px `[pattern:components-catalog#scrollspy-side-index]`, and the site cited for it ships none at all while opening its menu by hover on desktop and by button on phones, with Usability its lowest axis at 7.17 `[site:seasats]` [verified]. The phone version here is the same list behind a ticket, whose label is the current chapter's number and a shortened title, the device the header of an archive uses on phones `[site:gehry-getty]` [verified].
- **Bind the mark to the scroll number, not to a guess.** A sticky numbered rail with an active state carries a twelve-chapter page, and its capture shows that state marking one chapter while another fills the screen `[site:shopify-editions-w26]` [verified]. The current chapter, the fills and the ticket here all read one measurement per Lenis scroll event: the viewport centre against cached chapter offsets. The nearest-midpoint rule, and switching it off above the first chapter and below the last, are the plugin's choice.

## Parameters
| | |
|---|---|
| Current chapter | the chapter whose midpoint is nearest `scrollY + innerHeight / 2`; none while the centre is above chapter 1's top or below chapter 6's bottom; offsets measured on load, resize, fonts and a `ResizeObserver`, never per frame |
| Scroll source | one: Lenis' `scroll` event, which it emits for its own frames and for native scrolls alike, so the page updates once per frame |
| Reading progress | `(centre − top) / height`, clamped 0–1; earlier chapters `1`, later `0`; written as `scaleX` on a 2 px rule only when it changes by `.001`; the ticket's rule the same, written only while the ticket shows |
| Marker | one 3 px bar centred on the list's 1 px track (`inset-inline-start`, inside the panel's gutter on phones); `translate3d(0, link top, 0)` and the link's height; `transform var(--dur-routine)` (`400 ms`) `var(--ease-out-expo)`; cuts when it first appears, then fades in |
| Jump | `lenis.scrollTo(section, { duration: 1.2, force: true, userData })` with Lenis' default expo-out curve; `scroll-margin-top` honoured; Lenis re-synced first if the page moved natively; a check at `1.8 s`, repeated every `1.8 s`, waits while Lenis still runs this glide (its `userData` names it) and lets go only when something else replaced it |
| Landing | `h2[tabindex="-1"].focus({ preventScroll: true })`, then `history.replaceState` to `#stage-n`: replaced, not pushed, so the address names the chapter the reader is on and Back leaves the guide rather than replaying every jump (the `#top` links and the no-JS anchors keep the native push) |
| Cancel | `touchmove`, `wheel`, or an arrow, Page, Home, End or Space key (not in a form field, Space not on a button) during the glide: `lenis.stop(); lenis.start()` ends the glide where it is unless Lenis has already taken a wheel step over; no focus move, no hash; a tap does not cancel |
| Ticket | below `900 px`; `position: sticky; top: 0`, `60 px` tall; "Stage" (visually hidden) + `n of 6` + the chapter's `data-short`, described by a hidden "Shows the list of all six stages"; its own 2 px progress rule; opened while not docked (the first screen, the page's end), it docks first with a `0.5 s` glide; a disclosure closed by Escape (focus back to the ticket), a pointer outside, Tab out of the nav, or a jump, which moves focus from the list to the ticket for the glide; opening it mid-glide stops the glide |
| Height profiles | one altitude scale for all six stages (`0–600 m` on one baseline, `y = 116 − m × .18` in a `600 × 120` box), dashed guides at 200 and 400 m, ground at 16 % ink |
| Lenis | `lerp: .1`, `autoRaf: false`, driven by `gsap.ticker`, `lagSmoothing(0)`; `smoothWheel` in the full tier only |

## Tiers
- **Full:** the marker travels on the routine band, jumps glide for 1.2 s, the ticket docks with a 0.5 s glide, the chevron turns, the open list fades and drops 8 px.
- **Reduced:** jumps and the dock are instant (`immediate: true`, which Lenis also forces for programmatic scrolls under the media query), the marker cuts, the chevron flips without turning, the list only fades; the current link, its colour, the fills and the focus move all stay. The same rules answer `html[data-motion="reduced"]`.
- **Static** (`html[data-motion="static"]`): as reduced, with no colour transitions and no fade.
- **Forced colours:** the marker and the fills' backgrounds are dropped by the browser, so the current link carries a `Highlight` outline and the rules are painted with `forced-color-adjust: none`.
- **No JavaScript:** the links are plain anchors to the chapters, the sections carry `scroll-margin-top`, and on a phone the list sits in the flow as a contents list (the ticket only collapses it once the script has run).

## Accessibility
The rail is a `<nav aria-label="Stages of the walk">` of links in an ordered list; the current one carries `aria-current="true"`, which a screen reader reads with the link. Each numeral is real text after a visually hidden "Stage ", so a link reads "Stage 1 Harbour Gate" with CSS and without it. Chapter headings are focus targets (`tabindex="-1"`), so after a jump the next Tab continues inside the chapter rather than back in the rail, and the heading is what is spoken; there is no live region. The phone ticket is a `<button aria-expanded aria-controls aria-describedby>` over the same list; Escape from anywhere in the list returns focus to it, and a jump from the list parks focus on it for the glide instead of dropping it on `<body>`. Links are 52 px tall (56 px in the phone list), the ticket 60 px; focus is a 2 px accent outline. The marker, the track, the rules and the altitude labels are decoration; each height profile is an `<svg role="img">` with a sentence for a label.

## Adapters

### React / Next
Keep the current index in a ref updated from a `useLenis` scroll callback and call `setState` only when the index changes, so a scroll does not re-render the page; write the fills' `transform` through refs. Do the jump in the click handler with `lenis.scrollTo(ref.current, { onComplete, userData })`, focusing the heading's ref in `onComplete`, and stop it in the cancel listeners with `lenis.stop(); lenis.start()` while `lenis.userData` is still yours. In Next, render the links as plain `<a href="#…">` (not `next/link`), so the router does not try its own scroll.

### Vue / Nuxt
A composable that owns the Lenis instance (or reads Nuxt's) and exposes `current`, `progress` and `jump(i)`; bind `:aria-current="i === current ? 'true' : null"` in the template and write the fills and the marker's transform in a watcher with template refs. Measure in `onMounted` and after `document.fonts.ready`; add the `touchmove`, `wheel` and `keydown` cancel listeners there and remove them in `onBeforeUnmount`.

### Webflow
- Designer: a Nav Bar or Div Block set to `position: fixed` holding a list of Link Blocks to the sections' IDs, each with a number, a name and a 2 px Div for the rule; one more Div for the marker. Give each section an ID, `data-chapter` and `data-short`, and each heading `tabindex="-1"` through custom attributes.
- Inject from Footer code, after Lenis: the module only measures, writes attributes and transforms, and calls `lenis.scrollTo`, `stop` and `start`.
- Build the phone ticket as a Button inside the same nav, hidden above the breakpoint; Webflow's own Dropdown component would put a second list on the page.
