## 1. Context

The repo `burgisimon/awards` currently contains a single file, `awardsworthysites.md`, listing 19 award-winning websites (Awwwards SOTD / Developer Award class work: Léo Parpeix, White Desert, Zero University, uAvionix, Seasats, Trevor Noah, United Carriers, Sondaven, Lama Lama, Floema, Oryzo, Shopify Editions Winter '26, Lando Norris, Mindmarket, Mont-Fort, Anime.js, The Line Studio, Igloo Inc, Slosh Seltzer).

The user wants a **Claude Code skill set** (one core skill plus sub-skills) that makes Claude design and build *award-worthy websites or single award-worthy components* in the same league as those sites: not copies, but work that shares their design language, motion vocabulary, component patterns, creative effects and tech stack. The reference point for how such a skill should be organised is the open-source **impeccable** skill (pbakaus/impeccable, v4.3.1).

This plan has two parts: (A) the research findings (per-site analyses + cross-site synthesis) that become the skill's reference material, and (B) the architecture of the skill set, followed by an individual plan for the core skill and each sub-skill.

## 3. What "impeccable" does (reference architecture)

Verified from the cloned repo (`skill/SKILL.src.md`, `skill/reference/*.md`, `plugin/`, `.claude-plugin/*.json`):

- **One skill, many sub-commands.** A single `SKILL.md` (~90 lines) with a `## Commands` table; every command is a *reference file* (`reference/<command>.md`, 30–850 lines) loaded on demand. `argument-hint` lists the sub-commands; routing rules: no argument → context-aware menu; explicit command → load its reference; otherwise general design work. Commands can be "pinned" as standalone `/command` shortcuts.
- **Command families:** Build (`shape`, `init`, `document`, `extract`), Evaluate (`critique`, `audit`), Refine (`polish`, `bolder`, `quieter`, `distill`, `harden`, `onboard`), Enhance (`animate`, `colorize`, `typeset`, `layout`, `delight`, `overdrive`), Fix (`clarify`, `adapt`, `optimize`), Iterate (`live`, `generate`).
- **Durable project context files:** `PRODUCT.md` (audience, purpose, constraints, voice), `DESIGN.md` (tokens/visual system, Google-Stitch-compatible frontmatter), per-surface briefs and a *direction contract* (THESIS / OWN-WORLD / STORY / FIRST VIEWPORT / FORM / FINISH) written before code.
- **Visitor modes** (Persuade / Operate / Read / Experience) calibrate how expressive each command may be.
- **"New work" flow** fights the model's default aesthetics: derive 7 concrete visual worlds from the audience's culture, a scripted dice roll (`concept-seed`) picks which directions are shown, a canon "standing exit" is always offered, then the world is committed (color strategy: Restrained / Committed / Full palette / Drenched; font reflex-list to avoid: Fraunces, Playfair, Cormorant, Syne, Space Grotesk, Space Mono, IBM Plex, Inter-as-display, DM Sans, Outfit, Plus Jakarta, Instrument Sans...).
- **Craft floor** = quality checklist + bans (contrast, spacing rhythm, type floor, one authored motion moment, states, themed browser surfaces; refuse identical card grids, hero-metric template, eyebrows/kickers, numbered section markers, gradient text, glass-by-default, side-stripe borders, hard offset shadows outside neobrutalism, mono-as-costume, system display faces, emoji icons, geometric masks, theme-by-habit).
- **Playbook shape of each reference file:** visitor-mode note → assessment (often two isolated passes: design + mechanical scan) → set a thesis → apply rules → verify list → hand-off to `polish`.
- **Agents:** `finish-reviewer` (fresh-context QA with a strict disposition vocabulary: recapture/rebuild/fix/ship), `documenter`, `asset-producer`, `manual-edit-applier`.
- **Tooling:** a Rust binary launcher (`impeccable context|detect|signals|...`) with 61 deterministic anti-pattern detectors, hooks (`PostToolUse` Edit|Write + `Stop`) that run the detector, a live-browser variant mode. Distributed as a plugin (`.claude-plugin/plugin.json` + `marketplace.json` at repo root → `/plugin marketplace add pbakaus/impeccable`).

Take-aways for our skill: keep a thin core SKILL.md + on-demand references; write durable project files; give every sub-skill the same playbook shape; ship a craft floor tuned to *award-site* patterns; ship a reviewer agent; distribute as a plugin. Do **not** copy impeccable's heavy binary tooling in v1 (scripts must stay Node/Bash so they run anywhere).

## 4. Claude Code mechanics we rely on (verified against code.claude.com docs, 2026-09)

- Skill locations: project `.claude/skills/<name>/SKILL.md`; plugin `<plugin>/skills/<name>/SKILL.md` invoked as `/<plugin>:<name>`. A repo becomes a marketplace with `.claude-plugin/marketplace.json` at its root (`/plugin marketplace add burgisimon/awards`), plugins live in e.g. `./plugins/<name>` with `.claude-plugin/plugin.json`. Test locally with `claude --plugin-dir ./plugins/<name>`, `claude plugin validate <dir>`, `/reload-plugins`; evals via `claude plugin eval`.
- Frontmatter fields: `name`, `description`, `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context: fork` + `agent`, `background`, `hooks`, `paths`, `shell`, `metadata`, `license`, `compatibility`. `description`+`when_to_use` truncated at 1,536 chars.
- Substitutions: `$ARGUMENTS`, `$0..$N`, named `$arg`, `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PROJECT_DIR}`; dynamic context via `` !`cmd` ``.
- Skills cannot call each other programmatically; sub-skills are either separate skills Claude routes to by description, or reference files loaded by the core skill. Custom agents in `agents/*.md` can preload skills via a `skills` field.
- Guidance: SKILL.md < 500 lines, progressive disclosure via `references/`, `scripts/`, `assets/`; make descriptions "pushy" (skills under-trigger); explain the *why* rather than shouting MUSTs.

### Site cards (what to carry into `references/sites/<slug>.md`)

**1. Léo Parpeix.** Concept: first-person craft manifesto. Flow: gated preloader (non-linear % counter, "Click to enter & enable sound") → two-state hero ("French / Interactive / Designer" resolving to "Creative / Passionnate / Art Director") → intro + showreel → 3 projects → full-viewport WebGL typographic break → 3 projects → hover-preview archive list → 3-line footer CTA. Projects carry a metadata quartet (name · discipline · year · "Team of N @Studio" + award tally). Type: Monument Grotesk (UI/body) + Avantt variable (display). Four named themes swapped per section (white / forest / yellow / cream-on-green). Signature: a 128² ping-pong velocity FBO fluid sim (advection-only, dissipation .96) feeding one full-frame post-process (UV distortion .0035 + chromatic aberration) so the whole page ripples in the cursor's wake; two-speed cursor (dot lerp .75 / ring lerp .22, ring 1.35× & dot 0.7× on hover, contextual pill badges drag/play/view/feed/copy, off on coarse pointers); scroll-scrubbed model rotation; page-transition SFX; opt-in ambient loop (.375) + SFX (.35). ## 6. Cross-site synthesis: the "award-worthy" pattern language (all 19 sites)

Batch D confirmed and extended the wave-1 picture: where real production bundles were readable (Lando, Mont-Fort) the stack was exactly **Lenis + GSAP ScrollTrigger + Three.js**, with KTX2/Basis + DRACO pipelines, WebGL split into its own chunk, self-hosted woff2 everywhere, no Google Fonts, no Tailwind in production (only in clones), Rive appearing on 2/4 sites as the authored-2D-vector layer beside GSAP/Three. Batch D had no serifs at all (variable grotesque, geometric sans, monospace); dark sites were warm-dark; one site flips its theme by scroll position; wide-gamut P3 is shipping. Two narrative models recur: **chaptered/spatial** (one continuous world, numbered chapters, jump rail, scroll → 0..1 → camera spline) and **faceted/multi-route** (a brand world of authored routes with choreographed transitions). Resize strategy must be decided up front (Lando reloads at 992 px). Reduced-motion evidence: none, again.

**Concept first.** Every site makes one concept do the work a feature list usually does (a coaster launched like a frontier model; a changelog as a gallery; scroll as a freight route; a manifesto you sign by drawing a zero; a mind as a collage). Pages are chaptered arguments/journeys with entrance-hold-exit beats, not stacks of sections. Interruption is a design tool (gates, a typographic break, a scenario triptych); rule-of-three content blocks recur; emotion precedes economics on big-ticket sites; a named villain appears on campaign sites.

**Copy.** Numbers, not adjectives (90°S, 8,000 nm, 500 km/h, 12 guests); dual units; verb-chain sentences; constraint-removal formula; two registers (poetic vs numeric) separated by chapter; conversion matched to stakes (enquire / book a call / waitlist-as-object), never "Get started".

**Colour.** Two to four tokens, treated as a system: one ground + one ink + at most one environmentally derived accent (freight blue, marine rust, brass, pop pink, signal green). Warm-shifted near-blacks (#1A1C1C, #100904, #292919, #2C2824, #37384c) instead of #000 unless diegetic (USAvionix). Light grounds are back (7 of 12 light-dominant). Chroma is often outsourced to imagery. Colour can be page-level animated state (Floema, Léo's four themes, Shopify's per-chapter accent).

**Typography.** Two-family contract (expressive display + neutral grotesque) or one characterful grotesque at display scale; licensed faces recur (Monument Grotesk + Avantt, Suisse BP Int'l ×2, BT Steinhart + Helvetica Now, KTF Metro, George X) but Google Fonts still won (Why Zero); small numbered/mono-ish labels as texture (01/02, metadata quartets, Roman numerals, telemetry); fluid `clamp()` scales; type becomes WebGL material at punctuation moments; big gutters (40–120 px → 20 px).

**Motion vocabulary.** GSAP is universal (12/12 where known); Framer Motion appears nowhere. Smooth scroll is a *decision*: (a) native + Lenis + ScrollTrigger (Léo), (b) studio abstraction (`@bsmnt/scrollytelling`), (c) hand-rolled lerp (Floema, 0.1), (d) fully virtual scroll float when the story must gate/hold/redirect (Why Zero), (e) native scroll with a DOM-tethered canvas (Lusion). House easing is expo-out (`cubic-bezier(.16,1,.3,1)` / `(.19,1,.22,1)`), ~1.5 s for hero-scale moments, faster exits; velocity is an input (bulge, distortion, fluid wake); staggered masked line reveals (`y:150%`, stagger .1); shared-element transitions are the money moment; loading is authored (counter with hold at 100 %, gesture gate, boot sequence, cinematic title card) and usually doubles as the sound-consent gesture; the last screen is authored too (particle footer, designed 404, tagged footers); custom cursors are two-speed/contextual and off on coarse pointers; sound is opt-in ambient + SFX.

**WebGL / 3D architecture.** "HTML does layout, WebGL renders": one canvas, planes mapped from `getBoundingClientRect()`, scroll → uniforms/refs not React state, scene-window mounting + disposal. Two philosophies: one global post-process unifier (fluid distortion + chromatic aberration) vs discrete narrative shaders (frost, burn, shred, tunnel). Cost-controlled depth: 2D-in-3D (Polaroid curl), depth-map parallax (2.5D), pre-rendered C4D sequences scrubbed on scroll, single hero object with inertia. Pipeline: Blender/C4D → glTF + Draco + KTX2/ETC1S + atlases, adaptive quality tiers measured from frame time, three-tier content fallback.

**Stack reality.** No single stack: Webflow + injected GSAP/WebGL (3 of 12, incl. an SOTM), Next.js (+ Contentful / Payload), Vite + vanilla Three, Vue, vanilla ES6 + OGL, Remix. What is shared is the architecture above, plus TypeScript, self-hosted fonts, headless CMS only when content volume demands it.

**Award mechanics.** SOTD scores cluster 7.2–7.9; Usability is the lowest sub-score on every scored site (7.16–7.51) and Creativity the highest on concept-led ones; a Developer Award accompanied nearly every SOTD (technical bar is non-negotiable); SOTMs went to Son Daven, Lama Lama, Shopify. Reduced-motion and keyboard paths are almost never documented, so treating them as first-class is the skill's deliberate improvement over the reference set, not a copy.

**Components catalogue (seen ≥2×).** Authored preloader; fullscreen nav overlay with numbered links; custom cursor; scroll-scrubbed hero object/scene; pinned chapter with scrubbed media; horizontal rail inside vertical page; infinite draggable plane / arc gallery; hover-preview archive list; ticker/marquee (rAF, mask fade, pause on hover); scrollspy side index; hold/drag-to-compare reveal; poster-scale case blocks; metadata-labelled project rows; spec/metric blocks; interactive map cards; edition/version switcher + local search; designed footer/404; easter eggs (dwell-gated, click-spawned).

3. **Font licensing** — corpus faces are mostly licensed; the skill defaults to verified open faces and names licensed ones as optional.
4. **Corpus confidence** — seven sites analysed without live search; cards carry labels; `awards:research` tops them up later.
5. **Original text** — reference prose must be original; impeccable's structure may echo, wording may not; NOTICE line in README. Plugin name stays `awards`, never "awwwards".
6. **Permission friction** — `allowed-tools` wildcards for `node …/scripts/*.mjs` in plugin skills are unverified; v1 leaves prompts on and documents a one-line settings allow rule.
7. **Eval runner** — `claude plugin eval` is absent in the installed CLI; use sub-agent runs (skill-creator method) and keep `run-evals.sh` for machines where `claude -p` works.
8. **Sandbox verification ≠ real GPUs** — SwiftShader proves correctness, not frame rate; recipes state device budgets and the tier hook, and README asks for a real-device pass before shipping.
